Kom i gang

Rekkefølgen for de første dagene. Én person setter opp skjelettet, så kan resten jobbe parallelt.

  1. Mappestruktur og pakker 
    LearnToDev/
├── Subapp1.Mvc/       Controllers, Models, ViewModels, DAL, Services, Views
├── Subapp1.Tests/     xUnit + Moq
├── Subapp2.Api/       fra uke 45
├── Subapp2.Client/    React, fra uke 46
├── docs/              erd-gruppe-v4.mermaid, .png
└── .gitignore         bin, obj, node_modules, dist, *.db

    Pakker i MVC: Microsoft.EntityFrameworkCore.Sqlite, .Design, Microsoft.AspNetCore.Identity.EntityFrameworkCore og .Identity.UI. Alle installerer dotnet-ef.

  2. Modeller og DbContext etter ER-diagrammet

    Fallgruvene i denne modellen:

    • Sammensatte nøkler med HasKey(x => new { x.PlayerId, x.SchoolId }) på PlayerSchoolProgress, JobRequirement og JobPrerequisite.
    • JobPrerequisite peker to ganger på Job. Konfigurer begge relasjonene eksplisitt med DeleteBehavior.Restrict.
    • Player.CurrentJobId er int? med DeleteBehavior.SetNull.
    • Unik indeks på Player.UserId.
    • Penger som int. SQLite kan ikke sortere eller summere decimal i databasen.
    • ApplicationDbContext arver fra IdentityDbContext.
  3. JSON-format og seeding

    Bli enige om formatet før noen skriver spørsmål. Det følger modellen:

    {
  "school": "Frontend",
  "isExamOnly": false,
  "levels": [
    {
      "level": 1,
      "compendium": "## HTML\n...",
      "questions": [
        {
          "text": "Hva står HTML for?",
          "explanation": "...",
          "options": [
            { "text": "HyperText Markup Language", "isCorrect": true },
            { "text": "...", "isCorrect": false }
          ]
        }
      ]
    }
  ]
}

    En DbInitializer leser filene ved oppstart når databasen er tom, og seeder boliger, jobber, oppgaver, krav og forutsatte jobber i samme omgang.

  4. Identity og Player

    Når en bruker registrerer seg, lages en Player i samme operasjon: startpenger, Telt, dag 1 og fulle timer. Seed én testbruker, siden innloggingsinfo skal stå i dokumentasjonen.

  5. Parallelt arbeid

    Når modell, migrering og seed er pushet til main, tar hver person én del: skoler og eksamen, jobber, dag og bolig, eller innlogging og tester.

Sett opp brettet

setup_board.py lager etiketter, felt, epos og alle sakene, og legger dem på prosjekt #2 med feltene utfylt.

  1. Rydd det gamle brettet

    Lukk eller slett saker fra tidligere forsøk, så dere starter med et tomt brett.

  2. Gi Status-kolonnene nye navn

    Backlog, Klar, Pågår, Til review, Ferdig. Gjør det før skriptet kjøres, så får alle saker status Backlog.

  3. Logg inn med GitHub CLI

    gh auth login og gh auth refresh -s project.

  4. Prøvekjør og kjør

    python setup_board.py --dry-run, deretter uten --dry-run. Saker som finnes fra før hoppes over.

  5. Lag visninger

    Board gruppert på Status, tabell gruppert på Uke, og tabell gruppert på Subapp.

Backlog

Alle sakene skriptet oppretter. Filtrer og grupper for å se hva som må gjøres når.
